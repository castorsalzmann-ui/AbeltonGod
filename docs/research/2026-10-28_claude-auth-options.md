# Research: Claude auth options for the Phase 04b orchestrator

_Date: 2026-10-28 · All sources opened on 2026-10-28. Prepares the D-008 confirmation the user has to give before Phase 04b (#23) starts. Prices and policy change often: re-check rows 1–9 and 12–15 on the day 04b starts._

Question: one user, Claude Max subscription, Windows, a local personal Python tool that calls Claude with tool use (`kick_generation`). Which auth routes are officially supported, what does each cost, and do the SDK limits from D-011 behave as `docs/research/2026-10-28_guard-sdk-mapping.md` assumed?

This note states what the sources say. It is not legal advice. Rows marked **interpretation** are my reading of the sources, not something they state directly.

### C. SDK limits (resolves the open points of the guard note)

| # | Finding | Confidence | Source |
| --- | --- | --- | --- |
| 14 | `ClaudeAgentOptions.max_turns: int \| None` = "Maximum agentic turns (tool-use round trips)"; it "counts tool-use turns only". `max_budget_usd: float \| None` = "Stop the query when the client-side cost estimate reaches this USD value. The estimate can pass this value, so leave headroom." Both default to no limit. | High (quoted) | [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python), [Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop) |
| 15 | **Stop behaviour:** when either limit is hit, the SDK emits a `ResultMessage` with `subtype="error_max_turns"` or `"error_max_budget_usd"`, `is_error=True`, the message in `errors`, and **no `result` text**. `total_cost_usd`, `usage`, `num_turns` and `session_id` are still present (`terminal_reason` can be `"max_turns"`). A single-shot `query()` then **raises** an exception carrying the error text (e.g. "Reached maximum number of turns"), so the loop must be wrapped in `try`. A streaming-input session (`ClaudeSDKClient`) stays alive. | High (quoted) | [Agent loop: Handle the result](https://code.claude.com/docs/en/agent-sdk/agent-loop), [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python) |
| 16 | **Budget overshoot:** spend is compared with the cap **after** each response arrives; the response that crosses the cap completes and counts, so spend can exceed `max_budget_usd` by one response plus running sub-agents. Sub-agent spend counts toward the cap (needs Claude Code ≥ v2.1.217). On `error_max_budget_usd`, `usage` leaves out the crossing response but `total_cost_usd` / `model_usage` include it. | High (quoted) | [Agent loop: Budget headroom](https://code.claude.com/docs/en/agent-sdk/agent-loop), [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking) |
| 17 | `total_cost_usd` is a **client-side estimate** from a price table bundled at build time, not billing data. Use `total_cost_usd` or `model_usage` (whole tree incl. sub-agents), not `usage` (main loop only). Per-step `output_tokens` on `AssistantMessage` is a placeholder; read output tokens from the result. **Interpretation** (the page does not mention subscription auth): with subscription auth this is an API-equivalent figure, not money charged (consistent with D-011). | High (quoted) for the page content; the subscription sentence is interpretation | [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking) |
| 18 | There is **no** per-response output-token option on `ClaudeAgentOptions`. The env variable `CLAUDE_CODE_MAX_OUTPUT_TOKENS` sets max output tokens "for most requests" and can be passed via `options.env`. `task_budget={"total": int}` is an API-side token budget (beta header `task-budgets-2026-03-13`); its exact semantics were not checked. | High for the option list; `task_budget` behaviour unverified | [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python), [Env vars](https://code.claude.com/docs/en/env-vars) |
| 19 | Hooks in Python: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `SubagentStart/Stop`, `Stop`, … are supported. Caveat: "Hooks may not fire when the agent hits the `max_turns` limit". | High (quoted) | [Hooks](https://code.claude.com/docs/en/agent-sdk/hooks), [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python) |

## Cost estimate for one `kick_generation` request (API key)

Policy limits: ≤ 8 model calls, ≤ 1500 output tokens per call, cap $0.25 (`config/guard-policy.json`). Prices from #12. **Input size per call is an assumption** (no measured value yet): system prompt + 3 tool schemas + 286 tool tokens + growing history ≈ 4,000 tokens per call on average, no cache. If the Agent SDK is run with Claude Code's preset system prompt and built-in tools, the input is much larger (size not measured) — use a short custom `system_prompt` and only our own tools.

| Scenario | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
| --- | --- | --- | --- |
| Worst case allowed by policy: 8 calls × (4k in + 1.5k out) = 32k in, 12k out | 0.128 + 0.240 = **$0.37** (over the $0.25 cap → guard/SDK stop) | 0.064 + 0.120 = **$0.18** | 0.0032 + 0.006 = **$0.01** |
| Plausible normal request: 3 calls × (3k in + 0.5k out) = 9k in, 1.5k out | 0.036 + 0.030 = **$0.07** | 0.018 + 0.015 = **$0.03** | ≈ **$0.002** |

Arithmetic only, from list prices; real cost depends on measured input size, caching (cache hits cost 5 % of input on Opus/Sonnet 5.5) and thinking tokens (the models page lists adaptive thinking as always on for Opus 5.5; for Sonnet 5.5 it lists "Adaptive" and I did not find an official statement of the default. Thinking tokens count as output and are not included above, so real output may be higher). With the Max 20x credit ($200/month) the "normal" Sonnet request would allow several thousand requests per month; with Max 5x ($100) half of that. Which Max tier the user has is **not known** to me.

## Consequences for the guard mapping (update for `2026-10-28_guard-sdk-mapping.md` in 04b)

- `max_turns` counts tool-use turns, not model calls. A request with N tool-use turns makes N + 1 model calls (the final text-only answer). Pass `max_turns = max_model_calls − 1` and let the guard count real calls. **Unverified:** whether a final text turn after the limit is still allowed — test with a fake/recorded run in 04b.
- `max_budget_usd` can overshoot by one response: pass the guard's headroom minus one worst-case call (≈ $0.05 on Opus 5.5 with 4k in + 1.5k out), or rely on the guard's own reservation.
- Per-call output cap: `options.env={"CLAUDE_CODE_MAX_OUTPUT_TOKENS": "1500"}` ("most requests", not all) — the guard must still check reported output tokens.
- Tool gating: use a `PreToolUse` hook (fires for every call incl. sub-agents), not `can_use_tool`. Handle the exception that `query()` raises after an error result.

## Entscheidungsvorlage für dich

**Empfehlung: API-Key aus einer Console-Organisation, die du mit deinem Max-Abo verknüpfst (monatliche API-Credits), Modell Sonnet 5.5 als Standard. Subscription-Login bleibt als zweite Einstellung im selben Schalter (D-008).**

Warum:
- **Kostet dich kein zusätzliches Geld.** Max enthält monatlich (laut Hinweis im Help Center vom 07.10.2026; die Credits-Seite selbst nennt kein Startdatum) $100 (Max 5x) bzw. $200 (Max 20x) API-Guthaben, ausdrücklich auch für das Agent SDK. Ein normaler Kick-Request kostet grob $0.03 mit Sonnet 5.5 (Annahme, siehe Tabelle).
- **Frisst nicht dein Entwicklungsfenster.** Über den Subscription-Login würden Produkt-Aufrufe vom selben 5-Stunden-/Wochenlimit abgehen wie deine Claude-Code-Sessions. Die API-Credits sind ein getrennter Topf.
- **Policy-sicher.** API-Key ist der Weg, den Anthropic für Programme mit dem Agent SDK vorsieht. Der Subscription-Weg ist für deine private Nutzung heute erlaubt, wurde aber 2026 schon einmal angekündigt geändert (und dann pausiert).
- **Echte Dollar-Grenzen.** Die Guard-Budgets entsprechen echten Kosten, und wenn das Guthaben leer ist, stoppen die Aufrufe — es wird nichts auf dein Abo gebucht. Zusätzlich kannst du ein Ausgabenlimit für einen eigenen Workspace setzen.

Nachteile / was du wissen musst:
- Einmaliges Setup: Console-Organisation anlegen, in claude.ai unter Einstellungen → Abrechnung verknüpfen (geht erst nach 7 Tagen Max, Verknüpfung lässt sich selbst nicht mehr ändern), API-Key erzeugen, in `.env` ablegen (nie ins Repo).
- Das Guthaben verfällt monatlich und ist bei ungewöhnlich viel Nutzung irgendwann leer; dann wartest du auf den nächsten Monat oder kaufst nach.
- Wenn `ANTHROPIC_API_KEY` global gesetzt ist, nutzt auch Claude Code ihn statt deines Abos: mit `-p` und im SDK immer, interaktiv nach einer einmaligen Rückfrage. Claude Code ist von den Credits **nicht** abgedeckt. Den Key also nur in der `.env` von AbeltonGod setzen, nicht systemweit.

Alternative, wenn du kein Setup willst: **Subscription-Login über das Agent SDK** (du bist in Claude Code schon eingeloggt, oder `claude setup-token`). Erlaubt für deine eigene, private Nutzung; kostet nichts extra. Nachteile: zieht vom selben Nutzungsfenster wie deine Entwicklung, die Dollar-Werte sind nur Schätzungen, und sobald AbeltonGod jemand anderes benutzen soll, ist dieser Weg nicht mehr zulässig.

Ich brauche von dir: (1) Welcher Weg — API-Credits (empfohlen) oder Subscription? (2) Hast du Max 5x oder 20x, und sind die API-Credits schon verknüpft? (3) Standardmodell Sonnet 5.5 okay, oder lieber Opus 5.5 (etwa doppelt so teuer, Worst Case über dem $0.25-Limit)?
