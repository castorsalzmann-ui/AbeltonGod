# PHASE 03 — Sample import into the Live project

**Status:** IN PROGRESS · **Agents:** `bridge-engineer` (+ `audio-engineer` for the library) · **Tested in:** user's machine

## Objective

A kick generated by the engine ends up usable on a track in the user's Live set, with files organised in the project folder.

## Prerequisites

Phase 01 and Phase 02 accepted. Research note on `create_audio_clip` (Phase 02, item 5).

## Scope

1. `src/library/`: project folder layout (`<Project>/Samples/Drums/Kicks/…`), safe unique naming, sidecar metadata kept next to the WAV. Layout configurable.
2. Import path A (preferred, Live ≥ 12.0.5): `ClipSlot.create_audio_clip(<absolute path>)` into an empty slot of a chosen or newly created audio track — via AbletonOSC or a minimal extension handler.
3. Import path B (fallback): open the folder in Explorer and give drag-and-drop instructions.
4. Action log entry for every import; undo via Live's undo where it applies.

## Out of scope

Arrangement view placement, warping/tempo matching beyond Live defaults, Claude.

## Acceptance criteria

- [x] CI: library naming/layout tests, no-overwrite test. (PRs #82, #91, #93, #95)
- [x] User-verified: a generated kick appears as a clip on an audio track and plays. (Live runs 2–4 on 2026-10-29, #50; run 4 incl. undo PASS)
- [ ] Capability `clip_slot.create_audio_clip` set to `tested` or `unsupported` with evidence.
- [x] Fallback documented and tried once by the user. (`docs/setup/SAMPLE_IMPORT_FALLBACK.md`; user 2026-10-29, #50)
